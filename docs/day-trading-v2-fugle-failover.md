# V2 Fugle 行情備援：實作與運維

更新日期：2026-09-08。本次只調整行情接收、來源判定與事件通知；**不需要 DB migration**，不改策略選股條件，不新增 MA5／MA60 價格門檻，也不開放真實下單。

## 預設與正式發布門檻

| 環境變數 | 預設 | 用途 |
| --- | --- | --- |
| `FUGLE_LIVE_ENABLED` | `true` | 啟用獨立接收服務；非接收時段會停止 WS／REST 並釋放 lease。 |
| `FUGLE_LIVE_PUBLISH_ENABLED` | `false` | 預設影子模式，Fugle 樣本不發布至正式策略行情。 |
| `FUGLE_LIVE_SUBSCRIPTION_LIMIT` | `300` | 設定的訂閱上限；不代表帳號已取得額度。 |
| `FUGLE_REST_REQUESTS_PER_MINUTE` | `600` | 全站 REST 預算設定上限；仍受實際回應額度與保留量限制。 |
| `FUGLE_FAILOVER_AFTER_SECONDS` | `10` | 逐股 WS 失效後使用合格備援行情的門檻。 |
| `FUGLE_RECOVERY_HOLD_SECONDS` | `30` | WS 持續健康後切回的等待時間。 |

正式發布須同時滿足：發布開關已開啟、REST 回應確認至少 600 次／分鐘、WS 可用訂閱上限至少 300、目標股票未超量，而且**全部目標股票都已收到訂閱 ACK**。首次確認須 WS 已連線；後續斷線會保留已確認的股票名單供備援接手，新加入但未確認的股票不能藉此繞過門檻。

目前正式主機帳號實測 REST 額度為 **60 次／分鐘**，先以影子模式驗證；額度未知或只有 60 時，WS 最多訂閱 5 檔。修改本地設定成 600／300 不會替帳號升級，也不能解除正式發布門檻。官方額度見 [Fugle 方案說明](https://developer.fugle.tw/docs/pricing/)。

## 接收與風控

- 正式架構為單 worker；同一憑證使用一條 WS，股票訂閱單一 `aggregates` 頻道。Redis 全局 lease 防止部署交接時兩個實例同時供價，失去 lease 即停止接收工作。REST 也使用共享 Redis 預算與 429 冷卻；正式環境 Redis 不可用時不繼續消耗配額。
- 股票使用真正的 `lastTrade.price/time`，微秒時間轉換後保留交易所時間；一般上市／上櫃成交量由張轉股。加權指數以 `IX0001` 每 5 秒 REST 接收，映射內部 `t00`，使用 `closePrice/closeTime`；指數成交量保留原單位，不乘 1,000。
- WS 的 `snapshot`、`data` 都必須通過 ACK／訂閱 ID 驗證。心跳、收件時間不會刷新成交時間；試撮、暫停撮合、缺五檔、未來時間與舊行情不能冒充可交易報價。
- 一般報價由既有週期合併處理，停牌／試撮仍立即使舊行情失效。289 檔快取、200 次合成回呼的平均接收成本由 7.826 ms 降至 0.039 ms；單次合併選擇約 13.9 ms。此為本機合成負載，未包含策略引擎發布成本。
- WS 約 10 秒失效後，逐股選用新鮮 Fugle REST，再選 TWSE MIS。**進場仍保留原有 15 秒報價與五檔時效保護**；備援也過期時停止進場。WS 持續健康 30 秒才切回，REST 在此等待期間仍持續補價，直到真正由 WS 接手。這些門檻不保證上游永不中斷。
- 來源標示為 `FUGLE` 或 `TWSE MIS`；傳輸方式另記 `FUGLE_WS`／`FUGLE_REST`。歷史快照 v2 逐樣本保存來源、單位、交易時段與連續性，兼讀 v1。來源／連續性改變後重新累積合格歷史，不將不同來源的成交量差額混算成連續訊號。

## 影子驗證、啟用與回退

1. 保持 `FUGLE_LIVE_PUBLISH_ENABLED=false`，檢查 Redis `moneymoney:day-trading-quote-pump` 診斷中的配額、leader、ACK、交易時間、新鮮覆蓋率、解碼錯誤及 `shadowWarmup`。
2. `shadowWarmup` 只表示實際行情的分鐘覆蓋與累積情況，**不代表策略回測、獲利證據或正式策略已暖機完成**。影子行情不下單、不觸發來源切換通知。
3. 完成帳號實際額度與全池驗收後，只將 `FUGLE_LIVE_PUBLISH_ENABLED` 設為 `true` 並套用部署；其餘策略與風控設定保持原值。開關不是額度或 ACK 檢查的替代品。
4. 回退時只將同一變數改回 `false`，即可停止 Fugle 正式發布、保留影子觀測與原 MIS 流程。若 MIS 本身仍故障，回退不會使它恢復；15 秒保護照常生效。

## 通知與去重

只有盤中、非影子且目前 lease leader 才觀測來源狀態；初始狀態不通知，切換／中斷／恢復須穩定 10 秒。正常指數 REST 不算股票切換備援。

`QUOTE_SOURCE_SWITCHED`、`QUOTE_SOURCE_RECOVERED` 使用既有郵件佇列；`QUOTE_SOURCE_UNAVAILABLE` 只建立畫面事件，避免與既有行情中斷郵件重複。Redis 保存待確認狀態，DB 提交後才推進；穩定事件 ID、每使用者唯一約束及每收件人郵件去重共同防止重啟重放。建立與提交事件前會重新確認 leader，失效則回滾。恢復通知不代表解除原有交易風控。
