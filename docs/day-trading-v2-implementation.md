# 當沖機器人2實作紀錄

## 現有架構與沿用項目

- 前端：Next.js 16、React 19、TypeScript、全站共用 CSS 與既有導覽容器。
- 後端：FastAPI、SQLAlchemy 2；啟動時由 `Base.metadata.create_all` 建立缺少的資料表。
- 資料庫：正式環境 PostgreSQL，開發與測試可使用 SQLite。
- 即時行情：沿用 TWSE MIS。既有 15 秒快照會聚合成「已完成」的一分鐘 OHLCV，尚未完成的當分鐘不送入策略。
- 歷史行情：目前沒有可驗證的歷史分鐘行情供應商。回測中心會回報 `MINUTE_DATA_REQUIRED`，不會以日 K 或稀疏快照製造當沖績效。
- 券商 API：專案目前沒有券商串接。真實交易固定鎖定；後端保留 `BrokerAdapter` 介面，未設定時採 fail-closed。
- 舊功能：舊當沖與舊超強 AI 的程式、API、資料表及直達網址保留；主導覽改由「當沖機器人2」統一呈現。

## 新系統邊界

- 五個策略只有 `LONG`：開盤區間突破、VWAP 回踩、爆量突破、假跌破反轉、尾盤續強。
- 型別與券商介面保留未來增加空方策略的能力，目前所有下單入口拒絕非做多流程。
- `PAPER`、`BACKTEST`、`LIVE` 是每筆訊號、委託、成交、持倉、交易與通知的必要欄位。
- 模擬交易使用使用者獨立資料；舊當沖交易不匯入新績效，避免不同成本及成交假設混算。
- 共用總資金固定 3,000,000 元；五台額度分別為 750,000、750,000、600,000、300,000、600,000 元。
- 所有金額與價格使用 PostgreSQL/SQLAlchemy `NUMERIC` 及 Python `Decimal`。

## 風控與成交規則

- 部位股數取「風險額度 ÷ 每股停損距離」及「可用額度 ÷ 成交價」較小者，再依整股/零股設定處理。
- 單筆風險 6,000 元；日損 12,000 元後新部位風險減半，24,000 元停機；最多三筆持倉，同產業最多兩檔。
- 同一股票只允許一筆未平倉部位；多策略同時觸發時取信心分數最高者，其餘寫入跳過原因。
- 累計成交以 `broker_execution_id` 去重；部分成交只增加實際成交股數。
- 預設成本：牌告手續費 0.1425%、2 折、最低 20 元；當沖賣出證交稅 0.15%；滑價 5 bps。參數均可由設定頁調整。
- 13:20 後禁止新倉，13:25 起執行強制平倉。固定停損、第一段 50% 停利、保本/移動停利及緊急全平倉共用同一成交結算函式。

## 回測規則

- 只接受一分鐘 OHLCV，訊號僅使用當下以前「已完成」的 K 棒。
- 訊號在下一根 K 棒開盤價加滑價成交，不把訊號價當成交價。
- 個別回測時每台各使用 3,000,000 元，結果不可直接加總。
- 組合回測共用 3,000,000 元，套用機器人額度、同時三筆部位及同股票去重。
- 每筆績效扣除買賣手續費、當沖稅、滑價及其他成本；交易少於十筆時勝率顯示樣本不足。

## 尚待外部資料完成的項目

- 選定並設定涵蓋上市、上櫃且可重播的歷史分鐘行情供應商。
- 選定台股券商，實作送單、取消、成交回報、重連後持倉/未成交委託同步及實際費用回報。
- 券商 sandbox 驗證通過後，才可開放真實交易二次確認；首次只能使用極小額度。
- Email 通知可沿用現有 Gmail 發送器，正式啟用前需設定寄件憑證與收件人。系統內通知和網頁提示已由唯一事件 ID 去重。
